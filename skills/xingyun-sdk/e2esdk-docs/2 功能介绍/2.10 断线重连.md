# 2.10 断线重连

网络与服务的偶发抖动会导致 E2E 控制面 WebSocket 断开。`XingyunAvatarAgent` 内置自动重连：先按可恢复关闭码做短重试，耗尽后再重新请求统一会话接口，恢复后回到运行状态。

## `reconnect` 配置

重连开关挂在构造参数 `reconnect`（类型 `AgentReconnectOptions`），不配置时按默认值生效。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `enabled` | `boolean` | `true` | 是否在可恢复关闭码下自动重连；关闭后遇到断线直接进入失败处理 |
| `maxAttempts` | `number` | `6` | 网络连接重试最大次数 |
| `initialDelayMs` | `number` | `500` | 首次重试的基础延迟（毫秒） |
| `maxDelayMs` | `number` | `8000` | 指数退避的最大延迟上限（毫秒） |

```javascript
import XingyunAvatarAgent from "@xmov/avatar/agent";

const agent = new XingyunAvatarAgent({
  containerId: "",
  container: document.getElementById("agent-avatar"),
  appId: "your-app-id",
  appSecret: "your-app-secret",
  gatewayServer: "https://nebula-agent.xingyun3d.com/user/v1/ttsa_v2/session",
  reconnect: {
    enabled: true,
    maxAttempts: 6,        // 短重试 6 次
    initialDelayMs: 500,   // 首次延迟 500ms
    maxDelayMs: 8000,      // 最长退避 8s
  },
  onMessage(error) {
    console.error("渲染错误", error.code, error.message);
  },
});
```

## 重连流程

E2E 控制面 WebSocket 异常关闭时，SDK 依据关闭码和服务更新事件选择恢复路径：

| 关闭码 | 判定 | 后续行为 |
|--------|------|----------|
| `4011` / `service_update` 事件 | 服务更新 | 使用同房迁移流程，见下文 |
| `1001` / `1006` / `1011` / `1012` / `1013` / `1014` | 可恢复 | 进入 `reconnecting`，自动重连 |
| `1000`（运行中出现）/ `4000` / `4001` / `4002` / `4009` / `4010` | 终止类 | 进入 `failed`，不自动重连 |

可恢复断线的完整流程：

```
断线（可恢复 close code）
   → AgentState 进入 "reconnecting"，停止活动录音
   → 短重试：沿用当前 E2E 地址与 token，初始 500ms 指数退避，上限 8s，最多 6 次
   → 短重试仍未连上：重新请求统一会话接口换取新的 E2E 地址与 token
   → 恢复成功后回到断线前状态（ready / running / stopped）；只有重新创建 Session 才更换会话 ID
```

- 状态通过 `onAgentStateChange` 感知：断线立即进入 `reconnecting`，恢复后回到 `running`（或断线前的状态）。
- 底层 socket 的 `idle / connecting / open / closed / error` 变化由 `onSocketStateChange` 给出。
- 短重试耗尽且重新建立会话仍失败时，触发 `E2E_RECONNECT_EXHAUSTED`，此时需销毁当前实例、检查网络与服务后重新初始化。

## 服务更新：`service_update` / 4011

服务端更新会使用独立的同房迁移流程。SDK 依据服务端提供的重连地址、token 和有效期迁移 E2E 连接，不走普通重试耗尽后的 DELETE / 新建 Session 兜底。

1. 进入 `reconnecting`，停止活动 ASR，并在服务端允许的时间内等待当前交互收尾。
2. 确认旧 E2E 连接关闭后连接新地址，避免同时保留两条控制连接。
3. 成功后恢复原 Agent 状态；ASR 回到 `idle`，不会重放旧命令，也不会自动重新开启录音。
4. 凭据无效/过期、音频停止失败或旧连接关闭超时会进入失败处理。由业务展示失败信息；需要结束会话时显式 `destroy()`，不要在迁移中自动创建第二个实例。

单独收到 4011 时，SDK 使用已持有的服务迁移凭据；如果没有有效凭据，不能假设必然恢复。同房迁移保持现有 Session，普通短重连也不等于创建新房间。

迁移错误：`E2E_SERVICE_UPDATE_INVALID`、`E2E_MIGRATION_TOKEN_EXPIRED`、`E2E_MIGRATION_AUDIO_STOP_FAILED`、`E2E_MIGRATION_CLOSE_TIMEOUT`、`E2E_MIGRATION_FAILED`，详见 [错误码](<../3 API参考/3.7 错误码.md>)。上述行为经过源码与 mock 测试核对；具体部署的滚动更新仍需真实服务验收。

## 恢复后的行为

重连成功不意味着对话自动续上，SDK 遵循以下约定：

| 项 | 行为 |
|----|------|
| ASR | 回到 `idle`，SDK 持有的采集已停止，**不会**自动重新开启 |
| 旧命令 | **不会重放**断线前的命令或未上传的音频 |
| 会话标识 | 短重连保留；重新创建 Session 才改变 `getSessionId()` |

使用外部 `inputStream` 时，原流仍由调用方负责，不能据此判断物理麦克风已关闭。业务应依据恢复后的实际状态更新界面。下面默认保持 ASR 关闭，仅在 `running` 时允许用户再次点击开启；恢复到 `ready` / `stopped` 不应误显示为可录音：

<!-- validate:ts -->
```ts
import XingyunAvatarAgent from "@xmov/avatar/agent";

export function createAgent(report: (message: string) => void) {
  return new XingyunAvatarAgent({
    containerId: "#agent-avatar",
    appId: "your-app-id",
    appSecret: "your-app-secret",
    gatewayServer: "https://nebula-agent.xingyun3d.com/user/v1/ttsa_v2/session",
    onMessage(error) {
      console.error("渲染错误", error.code, error.message);
    },
    agentCallbacks: {
      onAgentStateChange(state) {
        console.log("Agent 状态", state);
        if (state === "reconnecting") {
          report("正在恢复连接，语音识别已暂停");
        } else if (state === "running") {
          report("已就绪，点击按钮重新开启语音识别");
        } else {
          report(`当前状态：${state}，暂不可开启语音识别`);
        }
      },
      onError(error) {
        if (error.code === "E2E_RECONNECT_EXHAUSTED") {
          report("重连失败，请稍后在服务端恢复后重新接入");
        } else {
          report(`${error.code}: ${error.message}`);
        }
      },
    },
  });
}
```

> `onError` 中的 `E2E_RECONNECTING`（正在重连）与 `E2E_RECONNECT_EXHAUSTED`（重连耗尽）是状态通知类错误，可作为界面提示，不要据此立即再新建第二个 `XingyunAvatarAgent` 实例。
