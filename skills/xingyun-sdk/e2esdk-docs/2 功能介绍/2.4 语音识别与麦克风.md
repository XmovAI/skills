# 2.4 语音识别与麦克风

本节说明如何用 `startASR()` / `stopASR()` 进行麦克风语音识别，以及音频分片与输入状态配置。

## 用户手势与权限

语音识别需要申请麦克风权限，浏览器要求：

- 页面运行在 **HTTPS 或 localhost** 安全上下文。
- `startASR()` 应由**用户手势**（如按钮点击）触发，直接随页面加载自动调用可能被浏览器拒绝。
- 浏览器支持 `navigator.mediaDevices.getUserMedia`。

## 开始识别：`startASR()`

申请麦克风权限并开始语音识别。识别文本通过 `agentCallbacks.onASRResult` 回调，是否自动进入 Brain 由生效的 `features.auto_send_asr_to_llm` 决定；设为 `false` 时可在业务确认后调用 `ask()`。

```ts
startASR(options?: AgentASRStartOptions): Promise<void>
```

```javascript
startButton.addEventListener("click", async () => {
  try {
    await agent.startASR();
  } catch (error) {
    console.error("ASR 启动失败", error);
  }
});
```

**行为要点**：

- 音频输入默认关闭。`startASR()` 会先打开音频输入，再申请麦克风并上传音频。
- 重复调用不会创建第二条采集链路。
- 权限、浏览器能力或音频转换失败时，Promise 会拒绝，同时经 `agentCallbacks.onError` 返回结构化错误（见下文「能力错误」）。

### 识别结果：`onASRResult`

同一段语音会先产出多条 `isFinal: false` 的中间结果，最终一条 `isFinal: true`。

```ts
onASRResult: (result: AgentASRResult) => void
// result: { text: string; isFinal: boolean; raw?: unknown }
```

```javascript
agentCallbacks: {
  onASRResult(result) {
    subtitle.textContent = result.text;
    if (result.isFinal) {
      saveFinalTranscript(result.text); // 只持久化最终结果
    }
  },
}
```

## 外部音频流：`startASR({ inputStream })`

可传入已有的 `MediaStream`，替代物理麦克风采集。SDK 从中选取第一条未结束的音轨并克隆；`stopASR()` / `destroy()` 只停止 SDK 持有的克隆，调用方负责释放原流。没有有效音轨时调用失败；即使使用外部流，编码和浏览器能力要求仍然适用。

<!-- validate:ts -->
```ts
import type XingyunAvatarAgent from "@xmov/avatar/agent";

// agent 已完成 init()；inputStream 由此业务独占并负责释放。
// 共享流应由原持有者决定释放时机，不能在这里停止其音轨。
export async function startExternalASR(agent: XingyunAvatarAgent, inputStream: MediaStream) {
  await agent.startASR({ inputStream });
}
export async function releaseExternalASR(agent: XingyunAvatarAgent, inputStream: MediaStream) {
  try {
    await agent.stopASR();
  } finally {
    inputStream.getTracks().forEach((track) => track.stop());
  }
}
```

## 停止识别：`stopASR()`

结束本轮识别并释放麦克风资源。

```ts
stopASR(): Promise<void>
```

```javascript
stopButton.addEventListener("click", async () => {
  await agent.stopASR();
});
```

**注意**：

- `stopASR()` 仅结束识别，并不等同于具身智能体播报结束判断（播报结束用 `onSpeakStateChange` / `onConversationChange`，见 `2.3`）。
- **打断（`interrupt()`）不会自动关闭 ASR**。需要结束监听时，应另行调用 `stopASR()`。

## 音频配置：`audio`

通过构造参数 `audio` 控制音频分片时长与初始输入状态。

```ts
interface AgentAudioOptions {
  inputEnabled?: boolean; // 仅设置通道初始状态，不自动开始采集
  chunkMs?: number;       // 默认 100；AEC 路径必须为 100
  echoCancellationEnabled?: boolean; // 已弃用的兼容回退项
}
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `inputEnabled` | `false` | 连接建立后的初始音频输入状态；默认关闭 |

```javascript
const agent = new XingyunAvatarAgent({
  // 省略公共参数
  audio: {
    inputEnabled: false, // 默认关闭，由 startASR() 再打开
  },
});
```

- 输入状态与 `startASR()` / `stopASR()` 联动：未开启时，`startASR()` 会先打开音频输入再开始采集；`stopASR()` 会关闭音频输入并释放资源。
- 空对象 `{}` 等于不传（使用默认值）。大多数业务不需要配置 `audio`，保留默认值即可。

以下场景可以显式配置：

- **服务端要求连接后音频输入初始为开启状态时**：可设置 `inputEnabled: true`。该配置只控制 E2E 音频输入通道的初始状态，不会自动申请麦克风权限或开始采集，业务仍需调用 `startASR()`。
- **希望按需申请麦克风、减少空闲占用时**：保持默认的 `inputEnabled: false`，适合按钮触发、按住说话、进入语音页面后再开启等常见交互。

## AEC 与音频路径

请求开启回声消除时，必须同时开启语音前处理。以下是构造参数片段：

```javascript
features: {
  speech_frontend: {
    enabled: true,
    enable_aec: true,
  },
}
```

`speech_frontend.enabled` 是语音前处理总开关；只设置 `enable_aec: true` 不满足服务配置要求。完整功能字段和嵌套规则见 [Features 功能配置参考](<../7 附录/Features 功能配置参考.md>)。

`features.speech_frontend.enable_aec` 是请求值。客户端按以下顺序确定是否启用双路上行：

1. Session 的 `e2e_resp.features.speech_frontend.enable_aec`；没有该值时读取顶层 `features.speech_frontend.enable_aec`。
2. 若服务端没有返回布尔值，使用构造时的 `features.speech_frontend.enable_aec`。
3. 再回退到已弃用的 `audio.echoCancellationEnabled`，最终默认 `false`。

服务端返回 `false` 会覆盖客户端的 `true`。以 Session 实际结果判断，不能只看本地配置。

- AEC 关闭：输入轨转换为 16 kHz 单声道后，经 MediaRecorder 编码为 WebM/Opus。
- AEC 开启：麦克风与数字人播放音频参与双路上行，采集/编码依赖 AudioWorklet、WebCodecs `AudioEncoder` 的 Opus 能力；`audio.chunkMs` 必须为 100。
- AEC 是服务端语音前端能力，不等于浏览器 `getUserMedia` 的 `echoCancellation` 约束。能力不足时不会自动切换为等价的 AEC 实现。

能力检测和错误处理见 [浏览器兼容性与故障排查](<../5 浏览器兼容性与故障排查.md>)。

## 能力错误

采集链路相关的失败经 `agentCallbacks.onError` 返回，常见能力错误：

| 错误码 | 含义 | 处理建议 |
|--------|------|---------|
| `MICROPHONE_ERROR` | 麦克风权限、设备或采集初始化失败 | 检查权限、输入设备与安全上下文 |
| `AUDIO_WEBM_OPUS_UNSUPPORTED` | 浏览器不支持 `audio/webm;codecs=opus` | 更换受支持的浏览器或设备 |
| `AUDIO_WEBCODECS_OPUS_UNSUPPORTED` | AEC 路径缺少 WebCodecs Opus 能力 | 检查实际编码能力和服务端 AEC 配置 |
| `AUDIO_CHUNK_DURATION_UNSUPPORTED` | AEC 分片时长不是 100ms | 使用默认 `chunkMs` |
| `AUDIO_CONTEXT_SUSPENDED` | AudioContext 未恢复 | 由用户交互触发后重试 |
| `AUDIO_ENCODER_ERROR` | WebCodecs 编码异常 | 停止本轮 ASR，排查设备与编码链路 |
| `MEDIA_RECORDER_ERROR` | 录制过程中 MediaRecorder 异常 | 停止本轮 ASR 后重试 |

错误结构为 `AgentError`（`{ code, message, domain, retryable?, cause? }`），`domain` 为 `permission` / `asr` 等，详见 `2.12 错误处理`。

```javascript
agentCallbacks: {
  onError(error) {
    if (error.domain === "permission") showMicPermissionHelp();
    if (error.code === "AUDIO_WEBM_OPUS_UNSUPPORTED") showBrowserUpgradeHint();
  },
}
```
