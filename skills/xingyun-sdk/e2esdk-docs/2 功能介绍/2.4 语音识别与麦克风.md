# 2.4 语音识别与麦克风

本节说明如何用 `startASR()` / `stopASR()` 进行麦克风语音识别，以及音频分片与输入状态配置。

## 用户手势与权限

语音识别需要申请麦克风权限，浏览器要求：

- 页面运行在 **HTTPS 或 localhost** 安全上下文。
- `startASR()` 应由**用户手势**（如按钮点击）触发，直接随页面加载自动调用可能被浏览器拒绝。
- 浏览器支持 `navigator.mediaDevices.getUserMedia`。

## 开始识别：`startASR()`

申请麦克风权限并开始语音识别。识别文本通过 `agentCallbacks.onASRResult` 回调，识别结束会自动进入 Brain 对话链路。

```ts
startASR(): Promise<void>
```

```javascript
startButton.addEventListener("click", async () => {
  try {
    await agent.startASR();
  } catch (error) {
    console.error("ASR 启动失败", error);
  }
});
```

**行为要点**：

- 音频输入默认关闭。`startASR()` 会先打开音频输入，再申请麦克风并上传音频。
- 重复调用不会创建第二条采集链路。
- 权限、浏览器能力或音频转换失败时，Promise 会拒绝，同时经 `agentCallbacks.onError` 返回结构化错误（见下文「能力错误」）。

### 识别结果：`onASRResult`

同一段语音会先产出多条 `isFinal: false` 的中间结果，最终一条 `isFinal: true`。

```ts
onASRResult: (result: AgentASRResult) => void
// result: { text: string; isFinal: boolean; raw?: unknown }
```

```javascript
agentCallbacks: {
  onASRResult(result) {
    subtitle.textContent = result.text;
    if (result.isFinal) {
      saveFinalTranscript(result.text); // 只持久化最终结果
    }
  },
}
```

## 停止识别：`stopASR()`

结束本轮识别并释放麦克风资源。

```ts
stopASR(): Promise<void>
```

```javascript
stopButton.addEventListener("click", async () => {
  await agent.stopASR();
});
```

**注意**：

- `stopASR()` 仅结束识别，并不等同于数字人播报结束判断（播报结束用 `onSpeakStateChange` / `onConversationChange`，见 `2.3`）。
- **打断（`interrupt()`）不会自动关闭 ASR**。需要结束监听时，应另行调用 `stopASR()`。

## 音频配置：`audio`

通过构造参数 `audio` 控制音频分片时长与初始输入状态。

```ts
interface AgentAudioOptions {
  inputEnabled?: boolean; // 初始化后是否立即开启音频输入
}
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `inputEnabled` | `false` | 连接建立后的初始音频输入状态；默认关闭 |

```javascript
const agent = new XingyunAvatarAgent({
  // 省略公共参数
  audio: {
    inputEnabled: false, // 默认关闭，由 startASR() 再打开
  },
});
```

- 输入状态与 `startASR()` / `stopASR()` 联动：未开启时，`startASR()` 会先打开音频输入再开始采集；`stopASR()` 会关闭音频输入并释放资源。
- 空对象 `{}` 等于不传（使用默认值）。大多数业务不需要配置 `audio`，保留默认值即可。

以下场景可以显式配置：

- **服务端要求连接后音频输入初始为开启状态时**：可设置 `inputEnabled: true`。该配置只控制 E2E 音频输入通道的初始状态，不会自动申请麦克风权限或开始采集，业务仍需调用 `startASR()`。
- **希望按需申请麦克风、减少空闲占用时**：保持默认的 `inputEnabled: false`，适合按钮触发、按住说话、进入语音页面后再开启等常见交互。

## 能力错误

采集链路相关的失败经 `agentCallbacks.onError` 返回，常见能力错误：

| 错误码 | 含义 | 处理建议 |
|--------|------|---------|
| `MICROPHONE_ERROR` | 麦克风权限、设备或采集初始化失败 | 检查权限、输入设备与安全上下文 |
| `AUDIO_WEBM_OPUS_UNSUPPORTED` | 浏览器不支持 `audio/webm;codecs=opus` | 更换受支持的浏览器或设备 |
| `MEDIA_RECORDER_ERROR` | 录制过程中 MediaRecorder 异常 | 停止本轮 ASR 后重试 |

错误结构为 `AgentError`（`{ code, message, domain, retryable?, cause? }`），`domain` 为 `permission` / `asr` 等，详见 `2.12 错误处理`。

```javascript
agentCallbacks: {
  onError(error) {
    if (error.domain === "permission") showMicPermissionHelp();
    if (error.code === "AUDIO_WEBM_OPUS_UNSUPPORTED") showBrowserUpgradeHint();
  },
}
```
