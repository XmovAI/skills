# 2.8 动作、行走与表情

本节说明如何让具身智能体在播报中做出肢体动作、行走，以及如何通过情绪标签控制具身智能体的面部表情与语音语调。

## 关键动作（Key Action）

具身智能体的肢体动作通过 SSML 中的 `<ue4event>` 标签下发，动作放在**哪句文本前面**，具身智能体就**边说那句话边做动作**。支持两种动作类型：

| type | 说明 |
|------|------|
| `ka` | 预设关键动作（预置动作编排名，如 `Elevate` / `KeyPoints` / `RightSide02`） |
| `ka_intent` | 关键动作意图：一个意图对应多个具体 KA，编排时由后端自动匹配最合适的实际动作 |

### 预设动作（`ka`）

`type="ka"` 通过 `data.action_semantic` 指定预置动作名：

```xml
<speak>
  真的特别感谢大家。
  <ue4event>
    <type>ka</type>
    <data>
      <action_semantic>RightSide02</action_semantic>
    </data>
  </ue4event>
  大家可以看向右上方。
</speak>
```

### 动作意图（`ka_intent`）

`type="ka_intent"` 通过 `data.ka_intent` 指定语义动作意图：

```xml
<speak>
  大家可以看向我的手指方向。
  <ue4event>
    <type>ka_intent</type>
    <data>
      <ka_intent>Pointscreen</ka_intent>
    </data>
  </ue4event>
  谢谢大家。
</speak>
```

### 动作意图列表（主要条目）

每个角色实际支持的动作意图数量存在差异，下表为主要意图条目，完整清单以服务端 / 星云平台为准：

| 点赞 | `Like` |
| 再见 | `Goodbye` |

| 指自己 | `PointingSelf` |
| 惊喜 | `Surprise` |
| 指屏幕 | `Pointscreen` |
| 比心 | `Heart` |
| 指观众 | `PointAudience` |
| 鼓舞激励 | `Encourage` |

> 关键动作是**定制化功能**，需要角色制作时预置动作编排。距离过近的多个 `ka` 会被忽略，一个 `<speak>` 中可嵌入多个 `<ue4event>` 依次生效。

## 行走

`XingyunAvatarAgent` 通过 `config.walk_config` 配置行走点位，运行期可用 `changeWalkConfig()` 动态更新。`WalkConfig` 字段如下：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `min_x_offset` / `max_x_offset` | `number` | 是 | 行走范围偏移限制 |
| `walk_points` | `{ [key: string]: number }` | 是 | 行走停靠点，key 为停靠点名称，value 为 x 坐标（像素） |
| `init_point` | `number` | 否 | 初始停靠点（x 坐标） |

> 行走属于**定制化角色功能**，需要角色制作时预置行走动画数据。坐标系原点为容器最左侧（x=0），范围为 0 到容器宽度。

### 构造时配置

```javascript
const agent = new XingyunAvatarAgent({
  containerId: "#agent-avatar",
  appId: 'your-app-id',
  appSecret: 'your-app-secret',
  gatewayServer: 'https://nebula-agent.xingyun3d.com/user/v1/ttsa_v2/session',
  onMessage(error) { console.error(error); },
  config: {
    walk_config: {
      min_x_offset: -400,
      max_x_offset: 400,
      walk_points: { left: 0, center: 400, right: 800 },
      init_point: 400,
    },
  },
});
```

### 运行时动态更新

> 注意：`changeWalkConfig()` 仅在具身智能体**非行走状态**下生效，正在行走时调用不生效，需等待行走结束后重试。

```javascript
agent.changeWalkConfig({
  min_x_offset: -400,
  max_x_offset: 400,
  walk_points: { left: 0, center: 400, right: 800 },
  init_point: 400,
});
```

### 通过 SSML 触发行走

配置好点位后，在 SSML 中嵌入 `<ue4event type="walk">`，`target` 指定目标停靠点名称，具身智能体会在播报到该处时走向目标点：

```xml
<speak>
  我先走到右边。
  <ue4event>
    <type>walk</type>
    <data>
      <target>right</target>
    </data>
  </ue4event>
  我过来了。
</speak>
```

| 属性 | 说明 |
|------|------|
| `<type>` | 固定为 `walk` |
| `<target>` | 目标停靠点名称，必须存在于 `walk_points`，否则行走指令被忽略 |

### 监听行走状态

通过 `onWalkStateChange` 感知行走开始 / 结束：

```javascript
const agent = new XingyunAvatarAgent({
  // ... 必填参数
  onWalkStateChange(state) {
    if (state === 'start') {
      console.log('具身智能体开始行走');
    } else if (state === 'end') {
      console.log('具身智能体到达目的地');
    }
  },
});
```


## 情感与表情

2.4.1 的 Agent `speak(ssml, is_start?, is_end?)` 没有第四参数，不支持通过 `extra.emotion` 设置单次播报情感。会话级 TTS 配置通过构造参数 `tts_config` 传递，见 [服务与大脑配置](<2.2 服务与大脑配置.md>)。

`tts_config` 是透传对象，客户端不校验厂商音色和情感枚举。只有服务端及所选 provider / 音色支持时，才使用其约定的 `emotion` 等字段；不能承诺面部表情与语音情感必然联动。角色动作、行走和面部表情也依赖角色素材能力。

关键动作仍可通过本篇 SSML 标签表达。不要把旧版 `XmovAvatar` 的第四参数复制到 Agent 示例中。
