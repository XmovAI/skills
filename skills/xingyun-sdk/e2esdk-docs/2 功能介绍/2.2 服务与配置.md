# 2.2 服务与配置

语音对话通常包含三个步骤：**识别用户说了什么、生成回复、将回复合成为语音**。这三个步骤分别由 ASR、Brain 和 TTS 完成，Features 用于调整它们之间的交互行为。

使用平台已有服务配置时，无需在代码中重复配置。本节介绍什么时候需要调整配置，以及常见场景下的填写方式。

## 1. 了解四项配置

| 配置项 | 作用 | 什么时候需要调整 |
|---|---|---|
| `asr_config` | **语音识别**：将用户语音转换为文本。 | 需要使用指定的识别服务或识别参数。 |
| `brain_config` | **回复生成**：由大模型或智能体处理提问，生成回复。 | 需要使用指定模型、智能体或模型扩展参数。 |
| `tts_config` | **语音合成**：将文本转换为语音。 | 需要更换音色，或调整语速、音调、情感等。 |
| `features` | **交互控制**：调整自动提问、语义抗干扰、回声消除等功能。 | 需要改变语音对话的处理方式或适应不同使用环境。 |

四项配置均为可选项，按需填写即可。例如，只想更换音色时，只需配置 `tts_config`。

## 2. 选择配置方式

### 使用平台已有配置

在星云平台应用管理中配置好 ASR、Brain 和 TTS 后，接入代码可以省略对应参数。

这种方式适合统一管理服务地址、模型和供应商凭证。生产环境涉及供应商密钥时，请优先在平台完成配置，避免将凭证暴露在浏览器代码中。

### 在代码中传入配置

需要自定义服务或调整功能时，在创建 `XingyunAvatarAgent` 时传入对应配置。

四项配置都与 `appId`、`gatewayServer` 等公共参数同级，**不放在 `config` 内**。省略某项或传入 `{}`，表示不提供该项的自定义配置。

下面的示例使用 `baseOptions` 表示快速接入中已准备好的公共参数，包括容器、应用信息、服务地址和必要回调。

## 3. 使用平台配置完成接入

平台已经配置好所需服务时，可以直接创建实例并初始化：

```javascript
const agent = new XingyunAvatarAgent({
  ...baseOptions,
});

await agent.init();
```

初始化成功后，可以发起文本提问：

```javascript
await agent.ask("请介绍一下你的功能。");
```

需要语音输入时，在用户点击“开始说话”等操作中调用：

```javascript
await agent.startASR();
```

配置识别服务不会自动启动麦克风。启动识别前应确认实例可见；麦克风权限、停止识别和音频能力见 [语音识别与麦克风](<2.4 语音识别与麦克风.md>)。

识别结果是否自动交给大模型，由 `features.auto_send_asr_to_llm` 的生效状态决定。

## 4. 按需调整服务

### ASR：指定语音识别服务

需要使用其他识别服务时，通过 `asr_config` 传入项目提供的完整配置：

```javascript
const agent = new XingyunAvatarAgent({
  ...baseOptions,
  asr_config: asrConfig,
});

await agent.init();
```

这里的 `asrConfig` 是已获取的有效配置对象，通常包含服务标识、服务地址、鉴权信息和识别参数。不同服务的字段要求不同，应使用同一套服务提供的配置。

ASR 负责将语音转换成文本。识别后直接生成回复，还是先让用户确认文本，由 Features 控制。

具体字段见 [ASR 配置参考](<../7 附录/ASR 配置参考.md>)。

### Brain：指定模型或智能体

Brain 可以连接模型服务，也可以连接已配置业务能力的智能体服务。使用哪种服务，取决于应用希望如何处理用户提问。

对于兼容 OpenAI 接口格式的模型服务，使用 `provider: "openai-compatible"`：

```javascript
const agent = new XingyunAvatarAgent({
  ...baseOptions,
  brain_config: {
    provider: "openai-compatible",
    base_url: "YOUR_SERVICE_BASE_URL",
    api_key: "YOUR_API_KEY",
    model: "YOUR_MODEL_NAME",
  },
});

await agent.init();
```

以上占位值需替换为实际配置，含密钥的示例仅用于本地测试或受控私有环境。

`openai-compatible` 表示服务采用兼容 OpenAI 的接口格式。具体使用哪家服务、哪个模型，由 `base_url`、`model` 等参数确定。

如果需要设置模型扩展参数，可以使用 `extra_body`。其字段和取值必须符合对应模型的要求，不同模型之间不能直接套用。

具体字段见 [Brain 配置参考](<../7 附录/Brain 配置参考.md>)。

### TTS：更换音色或调整合成效果

不填写 `tts_config` 或传入 `{}` 时，使用平台默认音色。

需要自定义音色时，必须同时填写三个非空字段：

| 字段 | 说明 |
|---|---|
| `provider` | 语音合成服务标识。 |
| `language` | 音色语种。 |
| `speaker_id` | 音色 ID。 |

例如：

```javascript
const agent = new XingyunAvatarAgent({
  ...baseOptions,
  tts_config: {
    provider: "XMOV_HN_TTS",
    language: "zh",
    speaker_id: "15",
  },
});

await agent.init();
agent.speak("你好，欢迎体验语音交互。");
```

示例中的音色应替换为当前环境可用的配置。音色 ID 的填写方式，以及语速、音调、情感等参数的支持范围，取决于所选服务。

完整规则见 [TTS 配置参考](<../7 附录/TTS 配置参考.md>)。

## 5. 调整语音交互方式

`features` 用于控制语音交互行为。所有开关都使用布尔值 `true` 或 `false`，**最终是否开启，以服务端接口返回的生效配置为准**。

### 场景一：识别后直接回复

标准语音对话可以请求开启自动提问：

```javascript
features: {
  auto_send_asr_to_llm: true,
}
```

该配置生效后，识别结果会自动交给大模型处理，业务无需再将同一段识别文本重复提交给 `ask()`。

### 场景二：用户确认文本后再回复

如果需要先展示转写文本，让用户修改、确认，或经过业务审核后再提交，可以请求关闭自动提问：

```javascript
const agent = new XingyunAvatarAgent({
  ...baseOptions,
  features: {
    auto_send_asr_to_llm: false,
  },
  agentCallbacks: {
    ...baseOptions.agentCallbacks,
    onASRResult({ text, isFinal }) {
      if (isFinal) {
        // 在页面展示文本，供用户确认或编辑。
        console.log("待确认文本：", text);
      }
    },
  },
});

await agent.init();

// 用户确认后调用：
async function submitConfirmedText(text) {
  const question = text.trim();
  if (question) {
    await agent.ask(question);
  }
}
```

关闭自动提问后，仍可接收识别结果。开始语音采集时，同样需要调用 `startASR()`。

### 场景三：语音处理能力

语音处理包含两部分，由服务端按生效配置提供，SDK 负责相应配置和音频传输：

1. 预处理：在 ASR 识别之前处理原始音频，例如回声消除；具体降噪能力以服务端支持为准。
2. 后处理：在 ASR 识别之后，校验识别结果并判断是否响应。

`features` 用于配置语音交互功能，包括自动提问、语义抗干扰、语音片段合并和语音前处理。所有开关均为可选布尔值。功能最终是否开启，以服务端接口返回的生效配置为准。

**预处理**：需要开启回声消除时，必须同时开启语音前处理：

```javascript
features: {
  speech_frontend: {
    enabled: true,
    enable_aec: true,
  },
}
```

仅设置 `enable_aec: true` 不满足配置要求，必须同时设置 `enabled: true`。

**后处理**：音量检测、重复文本检测、语义检测、语音片段合并等功能，见 [Features 功能配置参考](<../7 附录/Features 功能配置参考.md>)。

> 以上 Features 示例都是构造参数片段，应放入创建实例时的 `features` 对象中。

## 6. 配置检查

遇到初始化失败或配置效果不符合预期时，可以先检查：

| 检查项 | 正确填写方式 |
|---|---|
| 配置位置 | `asr_config`、`brain_config`、`tts_config`、`features` 与 `appId` 同级。 |
| 配置格式 | 传对象，不传 JSON 字符串、数组或 `null`。 |
| 服务信息 | 服务标识、地址、鉴权信息和模型名称相互匹配。 |
| 自定义音色 | 同时填写非空的 `provider`、`language`、`speaker_id`，并确认音色在当前环境可用。 |
| 功能开关 | 使用布尔值，按要求填写嵌套对象，并以服务端返回的生效配置为准。 |
| 回声消除 | `speech_frontend.enabled` 和 `speech_frontend.enable_aec` 同时设为 `true`。 |
| 语音输入 | 初始化成功且实例可见后，在用户操作中调用 `startASR()`，并允许麦克风访问。 |

完整字段、服务差异、高级配置和旧配置迁移规则，请查阅附录中的四篇配置参考。
