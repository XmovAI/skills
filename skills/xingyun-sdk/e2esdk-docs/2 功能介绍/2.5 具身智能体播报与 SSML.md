# 2.5 具身智能体播报与 SSML

本节说明如何通过 `speak()` 与 SSML（语音合成标记语言）让具身智能体播报文本，并配合停顿、注音、动作、控件指令同步表现，最后用播报回调感知进度。

## 方法：`speak()`

具身智能体的播报统一通过 `XingyunAvatarAgent` 提供的 `speak()` 发起：传入 SSML 文本，具身智能体按顺序边说边执行其中嵌入的指令。

**签名**

```ts
speak(ssml: string, is_start?: boolean, is_end?: boolean, extra?: object): string | undefined
```

**参数**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `ssml` | `string` | 是 | — | SSML 播报内容，必须包裹在 `<speak>` 根标签内 |
| `is_start` | `boolean` | 否 | — | 标识是否为分段播报的首段（见「分段播报」） |
| `is_end` | `boolean` | 否 | — | 标识是否为分段播报的末段 |
| `extra` | `object` | 否 | — | 附加参数，如 `{ emotion: "happy" }` 指定情绪，见 `2.8 动作、行走与表情` |

**返回值**：`string | undefined`，本次播报的请求 ID（`client_speak_id`），可用于关联 `onSpeakStateChange` 回调。

**示例**

```javascript
const speakId = agent.speak('<speak>你好，欢迎体验具身智能</speak>');
console.log('本次播报 ID:', speakId);
```

## SSML 根标签与基础标签

SSML 是驱动具身智能体**播报、停顿、注音、动作、行走、控件**的统一语言。所有内容必须包裹在 `<speak>` 根标签内：

```xml
<speak>
  ... 文本与指令 ...
</speak>
```

### 停顿 `<break>`

在句子之间插入停顿，通过 `time` 属性指定时长：

```xml
<speak>
  第一句话。
  <break time="500ms"/>
  停顿半秒后说第二句话。
</speak>
```

| 属性 | 说明 |
|------|------|
| `time` | 停顿时长，如 `500ms` / `1s` |

### 注音 `<phoneme>`

为多音字、生僻字标注正确读音，TTS 按拼音发音：

```xml
<speak>
  这项<phoneme py="mei3 di4">美的</phoneme>技术正在改变世界。
</speak>
```

| 属性 | 说明 |
|------|------|
| `py` | 拼音标注，如 `mei3`（美三声）、`di4`（的四声），多字用空格分隔 |

> 生僻字、特殊字符（全角双引号、`&` 等）可能导致服务端异常，建议在送入 `speak()` 前做预处理过滤。

## SSML 事件标签

除纯文本外，SSML 还支持两类事件标签，用于在播报过程中触发动作或控件：

| 标签 | 类别 | 说明 |
|------|------|------|
| `<ue4event>` | 内置事件 | SDK 内置：**关键动作**（`ka` / `ka_intent`）、**行走**（`walk`），详见 `2.8 动作、行走与表情` |
| `<uievent>` | 自定义控件 | 应用层控件：图片 / 视频 / 链接 / 文本卡片 / 3D 模型 / 背景音乐，详见 `2.9 UI 组件（Widget）` |

一条 SSML 可以混用多个标签，具身智能体会按顺序边说边执行：

```xml
<speak>
  大家好。
  <ue4event><type>ka</type><data><action_semantic>Elevate</action_semantic></data></ue4event>
  请看大屏幕。
  <uievent><type>show_image</type><data><image>https://example.com/slide.png</image><title>产品路线图</title></data></uievent>
  这是今天的主题。
</speak>
```

## 分段播报（`is_start` / `is_end`）

对较长的内容，可将一段话拆成多段依次调用 `speak()`。首段传 `is_start = true`，末段传 `is_end = true`，中间段两者均省略。具身智能体会把这些分段视作一次连续播报：

```javascript
// 首段
agent.speak('<speak>欢迎来到发布会。</speak>', true, false);

// 中间段（可多次）
agent.speak('<speak><break time="300ms"/>今天介绍三款新品。</speak>', false, false);

// 末段
agent.speak('<speak>感谢大家的聆听！</speak>', false, true);
```

> 分段播报时，`onSpeakStateChange` 的 `'speak_end'` 只在整个分段序列结束时触发，可据此判断一次完整播报是否结束。

## 播报状态回调

以下两个回调控件挂在构造参数顶层（均可选）：

### `onVoiceStateChange(state, duration?, client_speak_id?)`

单段语音（voice）开始 / 结束播放时触发，一段 speak 中可包含多段 voice。

| 参数 | 类型 | 说明 |
|------|------|------|
| `state` | `string` | `'start'` 语音开始播放；`'end'` 语音播放结束 |
| `duration` | `number` | 语音时长（毫秒），仅在 `'start'` 时提供 |
| `client_speak_id` | `string \| number` | 关联本次 `speak()` 的请求 ID |

```javascript
const agent = new XingyunAvatarAgent({
  // ... 必填参数
  onVoiceStateChange(state, duration, client_speak_id) {
    if (state === 'start') {
      showSpeakingIndicator(true);
    } else if (state === 'end') {
      showSpeakingIndicator(false);
      console.log(`[${client_speak_id}] 语音播放结束，时长 ${duration}ms`);
    }
  },
});
```

### `onSpeakStateChange(state, client_speak_id)`

整次说话（speak）状态变化时触发，用于关联 `speak()` 调用并判断一轮播报的完成。

| 参数 | 类型 | 说明 |
|------|------|------|
| `state` | `string` | `'speak_start'` 开始说话；`'speak_end'` 说话结束；`'speak_error'` 说话出错 |
| `client_speak_id` | `string \| number` | 本次说话的唯一标识，对应 `speak()` 的返回值 |

```javascript
const agent = new XingyunAvatarAgent({
  // ... 必填参数
  onSpeakStateChange(state, speakId) {
    switch (state) {
      case 'speak_start':
        console.log(`[${speakId}] 开始说话`);
        break;
      case 'speak_end':
        console.log(`[${speakId}] 说话结束`);
        agent.interactiveidle(); // 结束后回到交互待机
        break;
      case 'speak_error':
        console.error(`[${speakId}] 说话出错`);
        break;
    }
  },
});
```

> 注意：`agentCallbacks` 内还有一个同名 `onSpeakStateChange(event)`，其参数为对象 `{ state, clientSpeakId, raw }`，与这里的顶层回调签名不同，两者可并存使用。
