# 5 浏览器兼容性与故障排查

本节给出 `XingyunAvatarAgent` 的浏览器能力矩阵、按症状排查表、错误码快速对照，以及一套可直接复制的自检清单。

## 浏览器版本要求

最低基线：

| 浏览器 | 最低版本 |
|--------|----------|
| Chrome / Chromium | 94+ |
| Edge | 94+ |
| Safari | 15+ |
| Firefox | 100+ |

满足版本只是「具身智能体渲染」的准入门槛，音频上行另有独立能力要求（见下）。除版本外还需满足：

- **WebGL2**：具身智能体渲染必需，不支持则无法出帧。
- **HTTPS 或 localhost**：`getUserMedia` 只在安全上下文可用。
- **容器显式宽高**：具身智能体 Canvas 填满容器，容器高度为 0 时不显示。

微信（Android）依赖系统 WebView 内置 Chromium 版本、微信（iOS）/WKWebView 跟随系统 Safari 内核；Electron 以打包时的 Chromium 版本与实际运行时探测为准。这些环境不能只按「浏览器名称」判定，建议用本节「自检清单」与兼容性诊断逐项核验。

## 能力矩阵

具身智能体渲染与对话音频走的是两套能力栈：渲染依赖 WebGL2；音频上行依赖麦克风采集与 MediaRecorder WebM/Opus 编码。下表是各关键 API 的支持与兜底情况：

| 能力 | 用途 | Chrome ≥94 | Edge ≥94 | Safari | Firefox ≥100 | 不支持时的兜底/影响 |
|------|------|:---:|:---:|:---:|:---:|------|
| WebGL2 | 具身智能体渲染 | ✓ | ✓ | ✓（≥15） | ✓（≥100） | 无兜底，具身智能体不渲染；经 `onMessage` 报 `60001`–`60007` |
| `navigator.mediaDevices.getUserMedia` | 采集麦克风 | ✓ | ✓ | ✓ | ✓ | 无兜底，ASR 无法启动 |
| `MediaRecorder` WebM/Opus | 音频上行**硬门槛** | ✓ 运行时探测 | ✓ 运行时探测 | ≥18.4 | ✓ 运行时探测 | 无兜底，返回 `AUDIO_WEBM_OPUS_UNSUPPORTED` |
| 16 kHz 单声道转换（Track Processor 优先） | 音频转换 | ✓ | ✓ | ✓（≥18） | 仅 Web Audio 路径 | 自动降级到 Web Audio，不致命 |

> 表中版本是 API 的资料基线，**不替代运行时探测**。浏览器对容器与 Codec 的支持常独立于 API 本身，判断是否真正可用应调用 `MediaRecorder.isTypeSupported("audio/webm;codecs=opus")` 实测。

## 按症状排查表

| 症状 | 可能原因 | 排查与解决 |
|------|----------|-----------|
| 无画面 / 黑屏 | 容器高度为 0；WebGL2 不可用或上下文丢失；`init()` 未完成或资源下载失败 | 给容器显式宽高；`getRenderState()` 应为 `rendering`；`onMessage` 捕获 `60001`–`60007`；确认 `onDownloadProgress` 到 100% 且 `getAgentState() === 'running'` |
| 有画面但无声音 | 音量 0；无音频输出设备；自动播放被浏览器拦截（未在用户手势后初始化） | `setVolume(1.0)`；检查 `onVoiceStateChange` / `onSpeakStateChange` 是否触发；在用户点击后调用 `init()` |
| 麦克风不通 / 无识别 | 非 HTTPS/localhost；权限被拒；无输入设备；浏览器缺 WebM/Opus；非用户手势 | 迁到 HTTPS/localhost；重新授权；`startASR()` 放入点击事件；探测 `MediaRecorder.isTypeSupported("audio/webm;codecs=opus")`；看 `onError` 的 `asr` 域错误码 |
| 音频卡顿 / 识别文本异常 | 网络延迟高；CPU 过载；编码队列积压（>2s） | `onNetworkInfo` 看 `rtt`；降低分辨率；遇到 `MEDIA_RECORDER_ERROR` 停止本轮 ASR 后重试 |
| CPU/GPU 高、帧率低 | 分辨率过高；多实例并存；低端设备 | 降低具身智能体分辨率；单页单实例；`onFPSUpdate` 观察帧率；不需要渲染时切隐身模式 |
| 断线频繁 | 网络抖动；服务端主动断开（配额/token 失效）；HTTPS 页面连到 `ws://` 被混合内容拦截 | 按 close code 分支处理（见下）；确认统一会话返回的是 `wss://`；`4009` 配额错误不要自动重试 |

## 错误码快速对照

`XingyunAvatarAgent` 有两条错误通道，均需处理：渲染层错误经构造参数 `onMessage`（`SDKError`，数字码）；Agent/ASR/Brain/网络/配额错误经 `agentCallbacks.onError`（`AgentError`，字符串码 + 域）。完整定义见「3.7 错误码」，下面是按场景的快速对照：

| 场景 | 优先查看 | 典型码 | 动作 |
|------|----------|--------|------|
| 具身智能体不渲染/黑屏 | `onMessage` | `60001`–`60007`（WebGL/上下文）、`10001`–`10004`（初始化） | 换浏览器或检查 WebGL2/资源 |
| 麦克风/编码问题 | `onError`（`asr` 域） | `MICROPHONE_ERROR`、`AUDIO_WEBM_OPUS_UNSUPPORTED` | 检查权限/安全上下文/能力探测/用户手势 |
| 连接异常 | `onError`（`network` 域） | `E2E_SOCKET_ERROR`、`E2E_RECONNECTING`、`E2E_RECONNECT_EXHAUSTED`、`E2E_CLOSE_<code>` | 等待重连或销毁重建 |
| 服务端拒绝 | `onError`（`brain`/`quota`/`ttsa` 域）或 close code | `4001`（token 无效）、`4009`（配额超限）、`4010`（服务端主动断） | 按码处理，配额错误勿自动重试 |

WebSocket 关闭码行为汇总：

| 关闭码 | 处理 |
|--------|------|
| `1001` / `1006` / `1011` / `1012` / `1013` / `1014` | 自动重连（短重试后再重请求会话） |
| `1000` | 用户主动销毁为正常；运行中出现视为终止 |
| `4000` / `4001` / `4002` / `4009` / `4010` | 不重连（路径未知 / token 无效 / session 不存在 / 配额超限 / 服务端主动断） |

## 自检清单

四个只读方法可快速定位问题层：`getAgentState()`（生命周期）、`getASRState()`（麦克风/识别）、`getRenderState()`（渲染）、`getStatus()`（具身智能体在线/可见状态）。

```javascript
function diagnose(agent) {
  console.log('[agentState]  ', agent.getAgentState());   // 期望 'running'
  console.log('[asrState]    ', agent.getASRState());     // 期望 'listening'（收听中）
  console.log('[renderState] ', agent.getRenderState());  // 期望 'rendering'
  console.log('[status]      ', agent.getStatus());       // 期望 0=online / 5=visible
}
```

对照判定：

| 检查项 | 方法 | 健康值 | 异常值含义 |
|--------|------|--------|-----------|
| 生命周期 | `getAgentState()` | `running` | `initializing`=初始化中；`reconnecting`=断线重连中；`stopped`/`failed`/`destroyed` 不可对话 |
| 麦克风/识别 | `getASRState()` | `listening` | `requesting-permission`=等授权；`failed`=采集失败；`idle`=未开启麦克风 |
| 渲染 | `getRenderState()` | `rendering` | `paused`/`stopped`=未在出帧；`init`=尚未渲染 |
| 具身智能体状态 | `getStatus()` | `0`（online）/`5`（visible） | `1`=offline（离线）、`4`=close、`6`=invisible（隐身） |

建议在 `agentCallbacks.onAgentStateChange`、`onASRStateChange`、`onRenderChange` 中同步刷新页面按钮与提示，使状态机判断与诊断输出一致：

```javascript
const agent = new XingyunAvatarAgent({
  // ...
  agentCallbacks: {
    onAgentStateChange(state) {
      // 仅 running 时允许发起对话/开启麦克风
      talkBtn.disabled = state !== 'running';
    },
    onASRStateChange(state) {
      micBtn.disabled = state !== 'idle' && state !== 'listening';
    },
  },
});
```

若四项状态均健康但问题仍在，再结合「按症状排查表」与兼容性诊断逐项核验浏览器能力（WebGL2、MediaRecorder WebM/Opus），并留存浏览器、系统、设备型号与测试日期归档。
